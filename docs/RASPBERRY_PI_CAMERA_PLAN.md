# 树莓派 USB 相机端开发方案

更新时间：2026-10-17。

本文细化 `CAMERA_CAPTURE_PLAN.md` 中第四项“树莓派程序、systemd 和配置示例”，作为后续开发依据。本次只整理方案，不代表已完成树莓派适配或实机验证。

## 1. 已确认环境

| 项目 | 当前信息 |
|---|---|
| 主机 | Raspberry Pi 4B，2 GB 内存 |
| 系统 | Debian 10 Buster；Python、OpenCV 版本和系统位数尚未取得 |
| 相机 | USB 摄像头，具体型号待补充 |
| 已有实测 | 用户通过 `cv2.VideoCapture(0)` 成功打开摄像头、读取画面并显示 |
| 网络 | Wi-Fi，由系统负责接入 |
| 设备关系 | 单培养箱、单相机；树莓派独立连接服务器，不经过 ESP32 |

用户实测支持选择 OpenCV 路线，但尚不能据此认定无桌面拍照、JPEG 写入、开机自启和公网上传已经验证。

## 2. 技术选择与兼容性

采用 Python + OpenCV，通过 Linux 的 USB 视频设备读取照片。沿用已实测的索引 `0` 作为初始设备配置；程序不使用 `imshow`、`waitKey` 或其他桌面窗口功能。

首版不要求升级系统、不编译 OpenCV，不引入 CSI 相机库、录像、视频流或远程预览。优先使用树莓派现有可用的 `cv2`，分辨率和曝光沿用设备默认值，不新增网页拍摄质量设置。

Buster 通常提供 Python 3.7，具体以树莓派输出为准。现有 `camera/simulator.py` 是开发模拟器，使用现代 Python 和 `websockets >= 14`，不能直接作为 Buster 客户端。树莓派程序独立适配，保持服务器协议不变：

- 以 Python 3.7 可运行的语法和标准库接口编写，不使用 `asyncio.to_thread` 等较新接口。
- 若实机确认为 Python 3.7，计划固定 `websockets==11.0.3`，使用兼容的连接 API 和 `extra_headers` 参数；安装与运行结果仍需实机确认。
- HTTP 上传使用标准库 `urllib.request`，不额外引入 HTTP 客户端。
- 如使用虚拟环境，需让其能访问现有 OpenCV；系统安装的 `python3-opencv` 可通过 `--system-site-packages` 使用，不默认重新安装另一套 OpenCV。
- 服务器继续使用现有 Python 环境，不随树莓派端降级依赖。

## 3. 服务器接入

以下信息来自 `REMOTE_ACCESS.md`、`REMOTE_ACCESS_GUIDE.md`、`server/README.md` 和当前服务器代码；本次未连接服务器验证部署现状。

| 项目 | 约定 |
|---|---|
| 服务器根地址 | `https://175.24.182.190` |
| 控制连接 | `wss://175.24.182.190/api/v1/camera-stream` |
| 图片上传 | `POST /api/v1/camera/captures/{task_id}/image?captured_at=<Unix秒>` |
| 相机标识 | `camera-001`，与服务器 `INCUBATOR_CAMERA_ID` 一致 |
| 来源识别 | 独立相机 Bearer Token，复用现有设备配置方式 |
| CA 证书 | 服务器 `/etc/incubator/certs/incubator-ca.pem` 的公钥证书 |

树莓派主动建立出站连接，不需要服务器访问树莓派，也不需要给树莓派开放公网端口。Wi-Fi 密码沿用系统配置，不写入相机程序。

HTTPS 和 WSS 使用同一 CA 文件校验现有服务器证书，不复制 CA 私钥，不关闭校验。不增加相机专属用户、权限分级或审批机制。

当前仓库的 `server/deploy/incubator-https.conf` 尚无相机专属 location。公网联调前需补充：

- 相机 WebSocket 转发和 Upgrade 请求头。
- 图片上传路由采用设备 Bearer 识别，不套用网页 Basic Auth。
- 图片请求体上限与服务器当前 16 MiB 上限协调，上传超时与任务超时协调。
- 不改变现有 ESP32 通道和网站访问方式。

这些配置属于总方案第五项部署工作；仅完成树莓派程序不足以证明公网闭环已可用。

## 4. 程序执行流程

1. 启动时读取配置、清理本程序专用临时目录中的遗留照片，并连接服务器。
2. 收到 `connected` 后发送 `hello`，随后每 10 秒发送心跳及真实忙状态。
3. 收到 `capture` 指令，先占用本机执行状态；已有任务时拒绝新任务，不排队。
4. 报告 `capturing`，得到确认后打开 USB 摄像头，读取有效帧。必要的曝光稳定等待由首次实拍确定，不预设长时间预热。
5. 记录取到最终照片帧时的系统时间，编码为 JPEG 临时文件，检查写入结果，并释放摄像头。
6. 报告 `uploading`，得到确认后通过 HTTPS 单次上传 JPEG，正文为原始文件字节，声明 `Content-Type: image/jpeg`。
7. 收到服务器成功响应后记录任务结果；完成状态由服务器保存照片后设置，客户端不自行宣布成功。
8. 无论成功或失败，删除临时照片；实际操作和清理结束后恢复空闲并报告心跳。

首版按任务打开并释放摄像头，不在空闲期间持续采集画面，不保留帧历史。服务器负责所有间隔调度；树莓派不运行第二套定时任务，断线期间不自行拍照。

JPEG 是首版编码选择，硬件具体分辨率、默认画面清晰度和编码效果仍需实拍确认。文件名和服务器最终保存位置继续由现有服务端规则决定。

## 5. 异常、超时与重连

- 打开失败、读取失败、JPEG 写入失败、状态确认失败和上传失败均记录明确原因；连接可用时报告失败。
- 不自动重试拍照或上传，不保留失败照片，不补传，不重发旧任务。
- 控制连接断开后允许重新建立连接。普通网络故障暂按间隔 5 秒重连，实际值可在联调时调整。
- 网络恢复只恢复接收新指令；已有任务不得借新连接继续回报或上传。若上传在断线时已经发出，等待该次请求结束并清理，不重新发起。
- 断线不等于摄像头或 HTTP 操作已停止。未结束的工作仍占用本机忙状态，不能因重新连接而并行执行第二项任务。
- OpenCV 读取可能阻塞，计划把单次摄像头采集放在子进程中，设置采集期限，超时后结束子进程并释放设备；控制连接继续处理心跳。线程取消本身不能保证停止设备读取。
- HTTP 上传放到后台执行，避免阻塞控制消息；停止或重连时需等待实际上传结束，不能只取消等待对象就把设备标为空闲。
- 采集期限初始暂定 30 秒，上传网络超时暂定 60 秒，状态确认暂定 10 秒。上传网络超时不等于整个任务的严格总时限；服务器当前 120 秒任务期限决定是否接受结果，迟到上传按现有规则拒绝。
- 树莓派系统保持时间同步，确保照片能够匹配服务器遥测时间；不自行通过服务器心跳修改系统时钟。

以上时间均为开发暂定值，尚未实机验证。日志由本机 `journalctl` 查看，不增加网页日志或上传日志服务。

## 6. 文件与部署落点

| 文件或目录 | 用途 |
|---|---|
| `camera/client.py` | 设备连接、心跳、任务状态、上传、重连与清理 |
| `camera/usb_capture.py` | OpenCV 单次采集入口及 JPEG 写入，由客户端启动子进程执行 |
| `camera/requirements-pi.txt` | 树莓派通信依赖，按实际 Python 版本锁定 |
| `camera/camera.env.example` | 服务地址、相机 Token、CA 路径、视频设备索引配置示例 |
| `camera/deploy/incubator-camera.service` | systemd 开机启动与异常退出重启 |
| `camera/README.md` | 安装、前台试运行、自启动、查看日志和停止服务说明 |

这些是计划新增内容，不在方案整理阶段创建运行代码。现有模拟器继续作为开发测试工具，不改成真实驱动。

树莓派建议安装位置：程序 `/opt/incubator-camera/`，配置与 CA 公钥证书 `/etc/incubator-camera/`，专用临时目录 `/var/lib/incubator-camera/tmp/`。

systemd 在网络就绪后启动，进程异常退出自动重启。服务使用有视频设备访问权限的普通账号（加入 `video` 组），不依赖桌面登录。网络就绪目标不能保证 Wi-Fi 已连通，客户端仍需处理连接失败和重连。

树莓派程序与服务器独立更新。首次安装先前台验证拍照与上传，再启用开机启动，避免同时运行测试预览与后台服务占用同一摄像头。

## 7. 开发顺序与验收

1. **采集适配**：基于现有 OpenCV 完成无桌面单张拍照、JPEG 写入、资源释放与采集超时；本地替身测试覆盖失败路径，实际照片由树莓派验证。
2. **客户端接入**：实现协议、状态确认、后台上传、真实忙状态、断线重连及临时文件清理；接入临时服务器验证，不操作现有实验设备。
3. **部署材料**：提供 Buster 依赖、配置示例、systemd 单元和运行说明。
4. **实机联调**：补齐服务器反向代理后，验证树莓派到服务器的 HTTPS/WSS 和网页浏览闭环。

每完成一项向用户汇报完成内容、验证结果及仍需实机检查的事项。

| 场景 | 验收结果 |
|---|---|
| 不启动桌面，手动请求一次 | 树莓派拍到一张 JPEG，网页可查看和下载 |
| 连续发起请求 | 同一时刻最多一个任务，忙时拒绝，不排队 |
| 启用间隔任务 | 按服务器节奏接收指令，不在树莓派重复调度 |
| 无相机或读取失败 | 有失败原因，摄像头资源释放，无遗留照片 |
| 摄像头读取阻塞 | 采集期限后终止，心跳线程或事件循环不被长期阻塞 |
| 上传成功或失败 | 本地临时照片均删除，不自动重传 |
| Wi-Fi 断开并恢复 | 连接恢复，不补拍旧任务、不补传旧照片、不并发占用设备 |
| 上传已发出时断线 | 以服务器保存结果为准，不重复上传，操作结束后才恢复本机空闲 |
| 开机或进程异常退出 | 服务自动启动或重启，启动清理遗留临时照片，不执行旧任务 |
| 系统时间正常 | 照片时间正确，可按现有 30 秒规则查询附近环境数据 |


同时确认运行预览脚本时实际使用的 Python 命令或虚拟环境、计划运行服务的 Linux 账号。摄像头型号、默认分辨率及一次拍照耗时可在首次实拍时补充；暂不要求远程登录密码或 Wi-Fi 密码。
