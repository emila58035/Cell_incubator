# 树莓派相机拍照功能方案

更新时间：2026-10-16。

状态：第一项“服务器手动拍照与照片上传闭环”已完成本地模拟验证，其余功能待开发。本文作为后续相机功能开发和验收的依据；硬件相关待定参数见第 9 节。本文描述目标行为，不代表当前服务器已经具备全部能力。当前接口契约与限制见 `../server/README.md` 第 10 节。

## 1. 目标与范围

树莓派驱动摄像头，接收服务器指令拍摄照片，将照片上传到服务器供网页浏览。

当前仅按一台培养箱、一台树莓派设计。树莓派作为独立设备连接服务器，不经过 ESP32 转发；其照片默认对应当前培养箱，不开发多设备关联管理界面。ESP32 固件不参与相机控制。

第一版包含：

- 手动单张拍照，一个按固定间隔执行的定时拍照任务。
- 树莓派在线状态，以及拍摄、上传、完成、失败等任务状态。
- 最新照片、按拍摄时间浏览历史照片、单张放大、下载原图。
- 照片详情显示附近时间的温度、湿度和 CO₂ 数据。
- 勾选照片、全选当前页、批量删除。
- 独立相机页面，以及培养箱详情页的最新照片入口。
- 查看时旋转、裁剪和翻转，原文件不变。

不包含：录像、多个定时任务、固定钟点拍摄、请求排队、任务取消、失败任务重新执行入口、上传重试、离线补拍、断线补传、断点续传、归档、网页日志、用户角色与照片专属权限管理。网页不提供拍摄分辨率和质量设置，也不生成独立缩略图。

## 2. 架构与职责

现有服务器使用 FastAPI、SQLite、Nginx 和静态网页，设备远控已有 WebSocket 通道。新功能沿用其通信方式，为树莓派增加独立相机通道，与 ESP32 遥测连接分开管理。

```text
网页按钮 / 服务器定时调度
            │
            ▼
服务器创建拍照任务 ──WebSocket──▶ 树莓派 ──▶ 摄像头
            ▲                       │
            ├────WebSocket 状态──────┤
            └────HTTP 上传照片───────┘
            │
            ▼
照片文件 + SQLite 任务与照片记录 ──▶ 网页浏览
```

| 部分 | 职责 |
|---|---|
| 树莓派程序 | 主动连接服务器、接收指令、控制相机、报告状态、上传照片、清理临时文件 |
| 服务器 | 保存定时配置、调度任务、下发命令、维护任务状态、保存和提供照片、关联查询环境数据 |
| 网页 | 手动拍照、设置间隔和开关、显示状态、查看和下载照片、批量删除 |

树莓派使用独立设备标识，复用现有 Bearer Token 方式识别来源。网页沿用网站现有访问方式，不增加相机专属登录、权限分级或审批流程；能进入网站的用户均可使用全部相机功能。

## 3. 拍照执行规则

### 3.1 单次拍照

1. 用户点击网页拍照按钮，服务器创建唯一任务编号。
2. 若设备在线且空闲，服务器通过 WebSocket 下发任务。
3. 树莓派确认执行，报告拍摄状态，拍摄到临时文件。
4. 树莓派报告上传状态，通过 HTTP 上传照片、任务编号和拍摄时间。
5. 服务器保存照片与对应记录后返回成功，并将任务标为完成。
6. 树莓派删除本地临时照片。

拍摄时间取树莓派实际拍摄时间，而非上传时间。树莓派需要同步系统时间；内部使用统一时间戳，间隔调度不依赖时区。

### 3.2 并发、离线与失败

- 从服务器接受拍照请求开始，到拍摄和上传结束，同一相机仅执行一个任务。
- 设备忙时，新的手动拍照请求立即失败并提示“设备忙”；定时触发跳过本次。
- 设备离线时，手动请求立即失败；定时触发跳过本次。设备恢复后不补拍。
- 不排队，不取消当前任务，手动拍摄不改变定时节奏。
- 拍摄或上传失败时记录原因，不自动重试。用户可再次点击拍照，创建新任务。
- 上传成功、失败均删除树莓派本地照片，不保留供后续补传；进程异常遗留的临时文件在启动时清理。
- 服务器没有收到明确结果时，通过任务超时结束等待，不无限停留在“拍摄中”或“上传中”。超时不代表树莓派物理操作已结束，设备仍忙时继续拒绝新拍摄。
- 断线或程序重启后不重新下发旧拍照命令。已被服务器终结的任务不再接受迟到上传；仅因同一任务重复传来上传请求，不应生成第二张照片记录。

上传失败且本地文件已删除时，照片无法恢复；这是已确认的处理方式。失败原因优先通过在线连接报告，无法报告时由服务器记录断线、超时等已知原因。

### 3.3 定时任务

- 仅有一个定时任务，配置为是否启用、拍摄间隔。
- 启用时立即尝试拍摄一次，随后按固定间隔触发。
- 时间点按触发节奏计算，不从上一张上传完成时重新计时。
- 忙、离线或上一次失败不会推迟后续触发时间，也不累计待执行次数。
- 修改已启用任务的间隔时，以修改时刻为新起点，下一次在新间隔后触发，不额外立即拍摄。
- 停用后不再触发新拍摄，已开始的任务继续完成。
- 配置持久化。服务器重启后，若任务处于启用状态，立即尝试拍摄一次，然后重新开始间隔周期；重启期间错过的拍摄不补。
- 重启后遗留的未完成任务结束为失败，不重新执行。启动时设备未连接，则立即尝试按离线规则跳过，等下一周期再执行。

## 4. 任务与通信设计

### 4.1 状态模型

| 状态 | 含义 |
|---|---|
| 等待执行 | 服务器已接受任务，等待树莓派确认；不表示存在请求队列 |
| 拍摄中 | 树莓派正在获取照片 |
| 上传中 | 照片已拍摄，正在上传到服务器 |
| 完成 | 服务器已保存照片及记录 |
| 失败 | 手动请求因离线或忙被拒绝，或执行中拍摄、上传、连接、超时失败 |
| 已跳过 | 定时触发因设备忙或离线未执行 |

正常路径为“等待执行 → 拍摄中 → 上传中 → 完成”，异常路径进入失败。失败和跳过记录包含原因。网页通过任务编号查询当前状态，无需展示虚假的百分比进度。

### 4.2 接口划分

以下是开发用接口草案，均为待新增接口。路径和消息字段可在实现时统一命名，必须保持本文的业务行为。

| 通道 / 接口草案 | 用途 |
|---|---|
| WebSocket `/api/v1/camera-stream` | 树莓派连接、心跳、空闲或忙状态、拍照指令、执行状态和失败原因 |
| `GET /api/v1/camera/status` | 查询在线状态、当前任务、定时配置与下次触发时间 |
| `POST /api/v1/camera/captures` | 手动拍摄，返回任务编号或明确的离线、忙错误 |
| `GET /api/v1/camera/captures/{task_id}` | 查询任务状态与失败原因 |
| `PUT /api/v1/camera/schedule` | 保存启用状态与间隔 |
| `POST /api/v1/camera/captures/{task_id}/image` | 树莓派上传照片和拍摄时间 |
| `GET /api/v1/camera/photos` | 按拍摄时间倒序分页列出照片 |
| `GET /api/v1/camera/photos/latest` | 获取最新照片信息；无照片时提供明确空状态 |
| `GET /api/v1/camera/photos/{photo_id}` | 获取拍摄时间、原图地址与对应环境数据 |
| `GET /api/v1/camera/photos/{photo_id}/file` | 查看或下载原始照片 |
| `POST /api/v1/camera/photos/delete` | 按所选照片编号批量删除 |

照片文件通过 HTTP 单次上传，不经 WebSocket 传输。服务器收到文件不等于任务完成，必须等文件和对应记录保存后才返回成功。

## 5. 存储与环境数据

### 5.1 服务器存储

- 图片存入固定的照片目录，不按设备、年、月、日建立多级目录。
- 文件名包含设备编号、拍摄时间和任务编号，避免同一时刻拍照重名；扩展名取决于实际格式。
- SQLite 保存定时配置、任务记录和照片记录，不存储图片二进制。
- 照片业务信息只保存拍摄时间；任务编号、设备标识、文件位置等必要关联字段照常保存。
- 不单独保存分辨率和文件大小，不把温度、湿度、CO₂ 复制到照片记录或写入图片。

| 数据 | 最小内容 |
|---|---|
| 定时配置 | 启用状态、拍摄间隔 |
| 任务记录 | 唯一编号、手动或定时来源、状态、创建及结束时间、失败或跳过原因 |
| 照片记录 | 唯一编号、对应任务、拍摄时间、文件位置 |

文件目录与数据库都属于需要保留的数据。具体备份方法、容量限制和清理周期后定，不在本阶段增加对象存储、自动归档或磁盘配额系统。

### 5.2 环境数据关联

照片详情查询当前培养箱中距离拍摄时间最近的一条遥测记录，要求时间差不超过 30 秒；等距时取较早一条。

- 展示该条记录的温度、湿度、CO₂ 和实际采样时间。
- 使用同一条遥测记录，不为三个指标分别挑选不同时间的值。
- 找不到符合条件的记录，显示“无对应环境数据”。
- 某个传感器数据无效时，沿用现有看板的无效状态展示，不显示为正常数值。
- CO₂ 沿用现有数据和显示口径，不在相机功能中新增单位换算。
- 关联在查看时完成，不保存独立快照；原遥测被清理后，该照片可能不再有对应环境数据。

### 5.3 下载、删除与保留

- 支持下载单张原图。下载不删除照片，也不修改原文件。
- 支持勾选照片、全选当前页，确认一次后批量删除。
- 删除包含照片文件、照片记录及对应拍照任务记录；不删除原始环境遥测数据。
- 删除失败时返回未完成的项目和原因，不将失败项目显示为已成功删除。
- 不包含归档功能，也不默认增加打包下载或跨页全选。
- 照片和任务采用统一保留周期；没有照片的失败、跳过记录按自身时间套用同一周期。
- 具体保留周期未确定，不预设自动删除期限；开发清理逻辑时再补充配置值与启用规则。

## 6. 网页设计

### 相机页面

- 顶部显示树莓派在线或离线、当前任务状态及失败原因。
- 手动拍照按钮；离线或忙时提示当前原因，服务器仍按同样规则检查请求。
- 定时任务开关、间隔设置和下次触发时间。
- 最新照片及按时间倒序分页的历史照片列表，显示拍摄时间。
- 列表使用原图缩小展示，不生成或保存独立缩略图。
- 照片详情支持放大、查看附近环境数据、下载原图。
- 查看时可旋转、裁剪和翻转，仅改变当前显示，不修改服务器原文件，下载仍得到原图。
- 勾选、全选当前页、批量删除及一次确认。
- 不增加日期、设备或任务类型筛选，历史照片通过分页浏览。

### 培养箱详情页

展示当前培养箱最新照片、拍摄时间及进入相机页面的入口；无照片时显示空状态。不增加设备关联配置界面。

## 7. 开发落点与部署

建议落点如下，文件名可根据实际实现调整，不预先建立复杂框架：

| 位置 | 工作内容 |
|---|---|
| 新增 `camera/` | 树莓派程序、配置示例、摄像头适配、systemd 单元与运行说明 |
| `server/app.py` 及必要的新模块 | 接口接入、相机连接、任务状态、定时调度、文件与环境数据查询 |
| `server/schema.sql` | 定时配置、任务、照片记录及必要索引 |
| `server/static/` | 相机页面、培养箱详情页照片入口 |
| `server/deploy/` | 新接口代理、上传大小和超时配置、照片目录权限及持久化部署 |
| `server/tests/` | 相机接口、调度、状态与网页验证 |

新增相机 WebSocket 和上传路由应使用设备 Bearer 鉴权，并配置独立的 Nginx location；图片上传大小与超时按后续实测设置，不套用遥测接口的小请求体限制。图片浏览和管理沿用网站现有访问方式。

定时调度仅运行一个实例，避免多 worker 重复触发。调度生命周期随服务器启动和停止，设备连接恢复不触发补拍。

树莓派使用 systemd 开机启动，进程异常退出自动重启；相机硬件调用通过独立适配层完成。树莓派与服务器分别部署和更新，日志先在树莓派本机查看，不增加网页日志功能。控制连接可重新建立，但不会因此重发旧拍照任务或照片。

## 8. 开发顺序与验收

### 开发顺序

1. 增加数据结构、接口与模拟相机，验证手动任务和文件上传闭环。
2. 实现单实例定时调度、重启恢复、忙与离线规则、失败原因与超时。
3. 完成相机页面、详情页入口、环境数据关联、下载与批量删除。
4. 实现树莓派程序、systemd 和配置示例，硬件确定后接入相机驱动。
5. 完成部署配置及实机联调，补充已实测的参数和运行说明。

模拟相机仅用于开发和测试，不将模拟照片当作实机拍摄结果。

### 当前进度（2026-10-16）

- 已完成：手动任务、相机独立 WebSocket、状态回报、HTTP 上传、原图读取下载、基础忙与离线拒绝，以及开发模拟器。
- 已验证：真实本机 HTTP/WebSocket 与临时数据库闭环、成功失败后临时照片删除、并发拒绝、重复和迟到上传拒绝、既有遥测和 ESP32 远控回归。
- 下一项：定时调度、任务超时与启动恢复。
- 未完成：网页、历史图库、环境关联、批量删除、自动清理、真实驱动、自启动与实机部署。

### 验收标准

| 场景 | 预期结果 |
|---|---|
| 在线空闲时点击拍照 | 只执行一次拍摄，状态推进，服务器保存原图并可浏览下载 |
| 任务执行期间再次请求 | 新请求被拒绝，不并行、不排队 |
| 相机离线 | 网页显示离线，手动请求立即失败，定时触发跳过 |
| 启用定时任务 | 立即尝试一次，之后按固定间隔触发 |
| 手动拍照或定时遇忙 | 不改变后续定时节奏，不补拍 |
| 修改间隔或停用 | 按第 3.3 节执行，停用不取消当前任务 |
| 服务器重启 | 启用配置保留，立即尝试一次，不重发旧任务、不补拍错过次数 |
| 拍摄或上传失败 | 有明确失败状态和原因，无自动重试，本地照片删除 |
| 上传未完成或连接中断 | 不错误显示完成，最终结果由已落盘结果或超时等规则确定 |
| 重复上传同一任务 | 不产生重复照片记录 |
| 环境记录相差 30 秒及以内 | 显示最近同一条记录与实际采样时间 |
| 环境记录超过 30 秒或不存在 | 显示无对应环境数据，不伪造数值 |
| 放大、旋转、裁剪、翻转 | 只改变查看效果，原图内容和下载文件不变 |
| 删除所选照片 | 照片文件及关联任务数据删除，原始遥测保留 |
| 树莓派开机或进程退出 | 服务自动启动或重启，不恢复旧拍照任务 |

针对任务状态、间隔调度和环境关联使用可控时间与模拟设备验证；网页验证覆盖拍照、空状态、照片浏览下载与删除。服务器既有遥测和 ESP32 远控应继续通过原有检查。硬件验收包含真实拍摄、上传和本地删除。
